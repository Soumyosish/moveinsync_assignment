# MoveInSync Play Store Review Assignment

This repository analyzes public Google Play reviews for the MoveInSync app, filters low-rated reviews, classifies recurring user pain points, and produces an automated engineering summary when sentiment thresholds are breached.

## Overview

The project is designed for a forward-deployed engineering assignment focused on customer sentiment recovery. It captures historical review data from Google Play, trims it to the relevant time window, and categorizes issues that appear repeatedly in ratings 1-3 stars.

The current workflow is:

1. Pull recent public reviews from the Play Store
2. Filter to low-rated entries
3. Classify the reviews into themes such as login/authentication, tracking, app stability, and operations
4. Save the output as CSV data files
5. Trigger a report when a threshold is exceeded
6. Publish the summary through GitHub Actions

## What the scripts do

### `src/file_name.js`

This is the main 12-month scraping workflow. It:

- calls the Google Play scraper
- paginates through review history
- filters to entries within the last 12 months
- keeps only reviews with a score of 1-3
- groups the reviews by category
- writes `moveinsync_12months_low_ratings.csv`

### `src/scrapeReviews.js`

This is a similar 6-month review collection script used for shorter-term sentiment tracking.

### `src/automate.js`

This script reads `data/moveinsync_12months_low_ratings.csv`, calculates the category percentages, and writes a critical alert report if any issue group crosses the configured threshold.

## Setup

```bash
npm install
```

## Run locally

```bash
node src/file_name.js
node src/automate.js
```

This will generate the CSVs and summary report under the `data/` folder.

## GitHub Actions pipeline

The workflow in `.github/workflows/scraper_pipeline.yml` runs on a weekly schedule and can also be triggered manually. It:

- checks out the repository
- installs Node dependencies
- runs the Play Store scraper
- evaluates anomaly thresholds
- creates a PDF report when needed
- commits generated artifacts back to the repo

## Key findings from the current dataset

The project identifies recurring negative sentiment in areas such as:

- login and OTP/session issues
- GPS tracking and map instability
- app stability and crash behavior
- operational and routing problems

The 12-month analysis in the current dataset shows the largest negative-review concentration in the following areas, with the exact percentages evolving as the data set changes:

- Login / OTP
- Operations and route friction
- Tracking/map-related issues
- App stability / crash reports

## Notes

- The project intentionally prioritizes evidence from the public review corpus rather than a small manually selected sample.
- The automation includes retry logic and rate-limit handling to make the scraper more resilient.
- The repository is structured for experimentation and monitoring, not as a production app itself.
